# Project Model

This project currently has three layers of reality:

1. **Fork authority layer**
   - repo-local docs, decisions, work-items, and diary entries
   - this is where local divergence becomes explicit and auditable

2. **Reference layer**
   - upstream `badlogic/pi-mono`
   - the DSPY proposal set captured in `softwareco/infra/issue-tracker`
   - these inputs inform local planning but do not outrank local fork decisions

3. **Execution layer**
   - current phase: control-plane bootstrap
   - next phase: upstream import/sync decision
   - later phase: bounded DSPY-oriented implementation slices
